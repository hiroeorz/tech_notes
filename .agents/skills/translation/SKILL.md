# 翻訳完全性チェック

コード変更後（新機能追加・不具合修正・UI変更など）に、ユーザーに表示される文言が全localeで翻訳されているかを確認し、抜けがなくなるまで翻訳を補完する。

本スキルが実行されたら、定義済みのサブエージェントを積極的に使うこと。
特に
* 翻訳補完・完全性チェック : translation

の使用を推奨する。
他のエージェントについても必要に応じて起動して作業を進めてください。
各サブエージェントが使用するLLMモデルについては、各サブエージェントで定義されているモデルを使用すること。

## トリガー

- feature-implementation または bug-fix などでコード変更を行った後
- UI、ビュー、flash、バリデーション、メール、JavaScript、翻訳ファイルを変更した後
- ユーザーから明示的に翻訳の完全性確認を依頼された場合

## 基本方針

- 本プロジェクトの対応localeは `config/locales/ja.yml`、`config/locales/en.yml` から確認した **ja / en**、既定localeは `config/application.rb` で設定された **`:en`** である。勝手にlocaleを追加・削除しない。
- 翻訳キーは機能・画面の責務が分かる名前を維持し、internationalization スキルの命名規則に従う（Stimulus向けは `js.*` 配下）。
- ユーザー向け文言のみを対象とし、ログ・監査記録・内部識別子は翻訳しない。記事タイトル・本文などDB側（`post_translations`）の翻訳と混同しない。
- 翻訳値は自然な表現にし、補間変数・HTMLエスケープ・複数形・敬語を原文と整合させる。
- 新しく追加したキーは全対応localeに必ず追加し、未翻訳キーが残らないようにする。

## チェック手順

1. `config/locales/` を読み、対象locale（ja, en）と既定locale（:en）を確認する。
2. 全localeファイル間で翻訳キーの集合を比較し、欠落しているキーを列挙する。
3. ビュー・コントローラ・モデル・サービス・メーラー・通知・JavaScriptを横断して、未翻訳の直書き文言を検索する（例: `flash`、`t("flash...")` の未追加キー、`errors.full_messages`、フォームラベル、メール本文、Stimulus配下の文言）。
4. 未翻訳キー・直書き文言があれば、translation エージェントを起動して翻訳を補完する。
5. 補完後、再度 1〜3 を実行し、未翻訳がなくなるまで繰り返す。

## 翻訳補完（translation エージェントへの委譲）

translation エージェントを task ツールで起動し、以下を含めて指示する。

- 対象locale（ja, en）、既定locale（:en）、翻訳ファイルの配置（`config/locales/ja.yml`・`en.yml`）
- 未翻訳キーリスト、直書き文言リスト
- 既存の翻訳の文体・敬語・命名規則
- 補間変数の保持、HTMLエスケープの有無
- 完了条件: 全対象localeで未翻訳キーがゼロ、直書きユーザー向け文言がゼロ、テストがパス

translation エージェントは以下を行う。

1. 未翻訳キーを既定localeの値を参考に各localeへ追加する。
2. 直書きユーザー向け文言を適切な翻訳キーに切り出し、全localeへ追加する。
3. 既存の翻訳と整合しない値を修正する。
4. `bin/rails test` など関連テストを実行し、翻訳が反映されることを確認する。

## ループ終了条件

以下がすべて満たされるまで繰り返す。

- 全対象localeファイル間でキーが一致している
- ユーザー向け直書き文言が残っていない
- 関連テストが全てパスしている
- セキュリティスキャンで翻訳ファイルに秘密情報が含まれていない

## 完了報告

報告は日本語で行う（中国語など他言語を混入させない）。

- 対象locale
- 追加・修正した翻訳ファイルとキー数
- 直書き文言の対応結果
- 未翻訳・未対応範囲（あれば）
- 実行したテストと結果
