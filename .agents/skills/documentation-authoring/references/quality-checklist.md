# 品質チェックリスト

成果物に該当する項目だけを確認する。

## 根拠と正確性

- [ ] 重要な記述をユーザー指示、既存文書、コード、テスト、設定のいずれかで裏付けた
- [ ] 現行動作、将来要件、推論、提案、未確定事項を区別した
- [ ] 根拠間の矛盾を黙って解消せず、採用根拠または未解決事項を示した
- [ ] 変動し得る外部情報には一次情報と確認日を付けた
- [ ] 人名、日付、URL、認証情報、環境値を創作していない

## 完全性

- [ ] 目的、読者、スコープ、対象外、前提、制約を示した
- [ ] 主体と権限を示した
- [ ] 正常系、異常系、代替フロー、空状態、境界値を必要に応じて扱った
- [ ] 入力、処理、出力、事前条件、事後条件を判断できる
- [ ] セキュリティ、性能、アクセシビリティ、運用、監査、移行への影響を検討した
- [ ] 未確定事項に確認内容または決定条件を付けた

## 一貫性と追跡可能性

- [ ] 用語、識別子、状態名、権限名、画面名を統一した
- [ ] 要件IDと受入条件が一対一または明示的な対応関係を持つ
- [ ] 要件、仕様、設計、実装、テストの対応を追跡できる
- [ ] 複数文書間の重複に正本を定め、参照関係を示した
- [ ] 実装済み、未実装、廃止予定を判別できる

## 読みやすさ

- [ ] 見出し階層が飛んでいない
- [ ] 一文に複数の独立要件を詰め込んでいない
- [ ] 曖昧な形容詞ではなく観測可能な条件を使った
- [ ] 表や図が本文の重複ではなく理解を助けている
- [ ] 対象読者に不要な実装詳細または業務詳細を除いた

## 更新品質

- [ ] 既存の明示指示、テンプレート、文体、リンクを保持した
- [ ] 関係のない箇所を変更していない
- [ ] 文書内リンク、ファイルパス、コマンド、見出し参照を確認した
- [ ] 変更に伴って同期が必要な関連文書を確認した
- [ ] 残る不一致、対象外、未検証事項を完了報告に含めた
